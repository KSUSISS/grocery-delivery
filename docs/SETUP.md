# КСтолу

Курсовая работа по дисциплине «Разработка корпоративных приложений».

## Стек

- Java 21 или совместимая более новая JDK.
- Spring Boot, Spring Web MVC, Thymeleaf, Bean Validation, Spring Data JPA.
- PostgreSQL, миграции Flyway.
- Maven Wrapper: отдельная установка Maven не требуется.

## Открытие в IntelliJ IDEA

1. Выберите **File → Open** и папку `D:\grocery-delivery`.
2. Дождитесь импорта Maven и загрузки зависимостей.
3. В **File → Project Structure → Project SDK** выберите установленную JDK (например, corretto-24.0.2).
4. Подготовьте локальную БД по инструкции ниже, затем запустите `GroceryDeliveryApplication` кнопкой рядом с методом `main`.
5. Откройте <http://localhost:8080>.

## Локальная база данных

Запустите Docker Desktop. Скопируйте `.env.example` в `.env`, замените значение `DB_PASSWORD` своим паролем и выполните `docker compose up -d db`. Создаются база `kstolu` и пользователь `kstolu`, порт доступен только на `localhost:5432`. Данные сохраняются в именованном томе Docker.

В конфигурации запуска IntelliJ укажите переменную окружения `DB_PASSWORD` с тем же значением. Docker Compose читает `.env`, но Spring автоматически его не загружает. Приложению доступны настройки:

| Переменная | По умолчанию |
|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/kstolu` |
| `DB_USERNAME` | `kstolu` |
| `DB_PASSWORD` | Обязательна, без значения по умолчанию |

Вместо Docker можно использовать установленный PostgreSQL и отдельную новую БД с правами создания таблиц. При запуске Flyway применяет `src/main/resources/db/migration/V1__delivery_core.sql`, Hibernate проверяет соответствие сущностей. Это единственный механизм создания схемы; вручную применять `docs/database/schema.sql` не нужно.

## Запуск из PowerShell

Укажите путь к установленной JDK, если JAVA_HOME еще не настроен:

```powershell
$env:JAVA_HOME = "$env:USERPROFILE\.jdks\corretto-24.0.2"
.\mvnw.cmd spring-boot:run
```

Перед запуском укажите также переменную окружения `DB_PASSWORD`. Пароли не сохраняйте в Git.

Проверка проекта (пароль рабочей БД не требуется):

```powershell
.\mvnw.cmd verify
```

## Текущее состояние

Реализованы семь таблиц, JPA-сущности, репозитории и транзакционный `DeliveryService` в пакете `ru.komissarov.grocerydelivery.delivery`:

- Регистрация курьера по ФИО, телефону и возрасту, отдельно от выхода на смену.
- Заказ с адресом одной строкой и типом «Квартира / частный дом».
- Случайный восьмизначный номер и поиск по нему; уникальность проверяется БД, при совпадении генерация повторяется. Завершенные номера не переиспользуются.
- Назначение, история переназначений, подтвержденная отправка, завершение заказа диспетчером и отдельное завершение смены.
- Проверки ролей, блокировки при параллельной работе и журнал событий.

Это внутренний слой приложения без HTTP-контроллеров. При добавлении веб-слоя идентификатор автора должен браться из аутентифицированного пользователя, а не из параметра запроса. Авторизация и создание рабочих учетных записей еще впереди; тестовые пользователи создаются только в временной тестовой БД. Главная страница пока остается стартовой, макет диспетчера к БД не подключен.

Тесты запускают собственный временный PostgreSQL через Zonky Embedded Postgres: Docker и постоянная БД для них не требуются. При первом запуске загружаются тестовые бинарные файлы PostgreSQL. Сервер останавливается при завершении тестового процесса. Проверяются миграция, JPA, рабочие сценарии, повторы номеров, ограничения БД и конкурентные назначение/закрытие смены. Модульные тесты проверяют доступ и отправку без подтверждения. Для совместимости с установленной Java Mockito использует подклассы без динамического подключения Java-агента.

Следующие этапы по заданию: авторизация и четыре ролевых интерфейса, каталог, корзина, состав заказа, email-уведомления, отчеты Excel или PDF. Меню сейчас не реализуется.
